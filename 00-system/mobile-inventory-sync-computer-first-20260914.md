建立日期：2026-09-14。用户希望在手机 ChatGPT 口述库存，并同步到电脑知识库及 GitHub；不使用 Remote 作为入口。

## 用户怎么用

- 本轮仅试用手机“个人AI知识库”项目中已经核验过的库存对话，聊天 ID 见下方。不覆盖项目内任意新聊天。

## 每次运行

1. 读取根 README、Agent 协议、本文件和状态；一次只处理这一聊天。先检查是否有未恢复的库存事务，并使用辅助工具恢复后再接新消息。禁止并行运行第二个库存同步器。
2. 用 `list_threads` 检查指定聊天的新状态，列表不足时仍通过已登记的 ID 定位。没有新消息、未完成的推送/回执或实际库存文件变化时立即结束，保持安静。不要每次运行提交检查时间，也不要重复推送相同回执。
3. 若聊天有变化，先 `navigate_to_codex_page` 打开该聊天刷新，再 `read_thread` 读取完整用户原文、消息 ID、角色、时间和分页。实测隐藏聊天读取可能是缓存；若返回的 thread.updatedAt 仍早于刚才 list_threads 的 updatedAt，不能当成新快照，也不能推进状态游标。可间隔 10 秒后先切到本地设置对话 `01a09b6f-bf1e-7e12-bd27-8530f0c96b16`，再重新打开指定手机聊天并读取（停留原页面单纯重复读取可能一直是旧缓存）。最多重试一次；仍旧则留待下轮并报告未完成。仅有摘要、截断内容、读不到完整边界或时间不明时不得入账。分页读到基线或已登记消息，按时间从旧到新处理。
4. 忽略所有助手消息、工具内容、标题、上传文件内容、引用/示例/假设/历史转述，以及所有以 `[库存同步回执]` 或 `【电脑库存核验回执` 开头的消息。我们用发送工具回传的内容也会显示为用户消息，因此不能只靠角色筛选。
5. 只接受基线之后、尚未登记、用户明确要求本次执行的库存指令。只说“黑色 12000”时不能判断增加还是盘点，请确认。查询只读取主记录并重新求和。同一消息 ID 只能记一笔；同样的文字出现在不同消息 ID 时，结合上下文判断是否重复发送，不能仅凭文字相同去重，也不能把催促同步当成新入库。
6. 修改前检查 Git 状态。不得把 `.obsidian/` 或无关改动带入提交；如果库存、索引或状态文件已有来路不明的修改/暂存，先停止并报告。只用辅助工具执行明确的变动：将 `thread_id`、`message_id`、完整 `source_text`、`color`、`operation`、整数 `quantity`、`date` 写入临时 JSON 后传给工具。不要用 shell 拼接聊天原文。待入账消息不要提前加入 `observed_message_ids`；`apply` 成功会自动登记。
7. 工具更新库存和事务记录后，检查明细合计、差异与消息 ID。只暂存工具实际修改的业务文件及状态，提交并推送 `origin/main`。遇到远程变更先核对，不覆盖、不强推、不重复执行同一增量。推送失败只保留并重试同一提交。
8. 在原手机对话发送简短回执，固定以 `[库存同步回执]` 开头，包含源消息 ID、核验时间、相关颜色和总库存，并分别写清电脑入账及 GitHub 推送的真实状态。查询回执也写明是已记录库存而非现场盘点。不要用“项目资料全部同步”等措辞。让手机助手简短转述回执，不执行新的库存操作。
9. 发送工具成功只算“已提交待核实”。刷新原聊天再读取，确认回执已出现后，将源消息 ID、回执消息 ID 和状态原子写入持久状态。未看到回执时先查找相同标记，不盲目重发、更不重新入账。登记查询、忽略和待确认消息，避免每次循环重复处理。状态文件要保留辅助工具的 `events` 及其他字段；不要覆盖其他流程的新状态。入账事件分别维护 `github_status`（pending/pushed 与 commit）、`receipt_status`（pending/verified 与消息 ID），查询回执登记在 `receipts`。完成后保存实际库存文件 SHA256 至 `last_reported_inventory_sha256`，并保存 `list_threads` 返回的聊天 updatedAt 至 `last_seen_cloud_updated_at`；不要把 read_thread 的另一种时间戳混用。最终状态变更也要单独提交和推送，避免重启丢失核验进度。
10. 后续读到对已入账消息的修改，不重新套用原增量，应以一条新明确指令处理。每次先完成已有待推送/待回传事务，才能处理下一笔。明确的澄清需求、失败或完成可通知；无变化保持安静。

## 辅助工具

在知识库根目录运行：

```text
python3 00-system/mobile_inventory.py snapshot
python3 00-system/mobile_inventory.py recover
python3 00-system/mobile_inventory.py apply --json /绝对路径/已核实指令.json
```

`operation` 分别用 `add`、`subtract` 或 `set`；JSON 的全部字段都必需。`duplicate: true` 表示这条消息已经入账，只能继续未完成的推送和回执，不得换一个 ID 再入账。工具错误必须先解决，不能绕过工具直接修改库存数量。
