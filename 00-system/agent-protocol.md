# Agent 工作协议

## 1. 读取顺序

处理知识库任务时，先读取：

1. 根目录 `README.md`
2. 本文件
3. 与任务相关的目录 `README.md`
4. `03-index/index.md`
5. 目标主题下的事实页和知识页

## 2. 新内容分流

### 原始内容

网页、书籍摘录、会议记录、对话、文件内容和个人观察，先写入 `04-inbox/`，保留：

- 获取时间
- 来源或上下文
- 原文或摘要
- 不确定的地方
- 可能的主题

### 项目资料

如果内容明确属于某个项目，整理后优先放入该项目的专题目录，并在专题目录内部按库存记录、知识、指南或决策等类型组织。项目资料不必强行拆回全局目录。

### 事实与知识

只有能说明“这条信息来自哪里”或“这是何时何地发生的观察”，才进入事实类目录。事实页避免加入没有来源支持的推测。

当内容已经完成提炼，能够回答“这意味着什么”“如何使用”或“与已有知识有什么关系”，才进入知识类目录。知识页应链接支撑它的事实页，必要时标记适用范围和局限。

## 3. 写入原则

- 不覆盖已有内容；更新前先阅读原文。
- 优先增量更新，避免为小改动重写整篇文档。
- 不确定的内容使用 `draft`，不要伪装成确定结论。
- 发现矛盾时保留双方记录，并在文档中明确写出冲突。
- 发现重复主题时，优先建立链接或合并，避免复制多份长期结论。
- 一次处理结束后更新 `03-index/index.md`，或者在 `03-index/inbox-triage.md` 留下待办。

## 4. 输出格式建议

事实页至少包含：

```markdown
# 标题

## 事实

## 来源

## 时间

## 可信度与限制

## 相关知识
```

知识页至少包含：

```markdown
# 标题

## 结论

## 解释

## 适用范围

## 支撑事实

## 相关主题

## 待验证问题
```

## 5. 完成检查

- [ ] 文件放在正确层级
- [ ] 项目资料已集中在对应项目目录内
- [ ] 文件名符合命名规则
- [ ] 有来源、时间或上下文
- [ ] 区分了事实、推断和建议
- [ ] 添加了相关链接
- [ ] 更新了索引或待办
- [ ] 没有把秘密、密码或个人敏感信息写入普通知识页

## 6. 版本控制与远程同步

- 用户偏好：知识库发生变动后，由 Agent 自动提交并推送到远程仓库。
- 每次处理完成后，只暂存本次任务实际修改的知识库文件，不把无关的用户改动带入提交。
- 提交信息应简要说明本次变动；默认推送到远程 `origin/main`。
- 推送前检查待提交内容，确认没有密码、令牌或其他敏感信息。
- 如果远程仓库不可访问、认证失败或推送冲突，不伪造成功状态；保留本地提交并明确告知用户。
- 这项约定仅适用于知识库相关改动，不自动处理其他目录或其他项目的文件。
