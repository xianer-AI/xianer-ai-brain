| 端 | 当前版本 | 对应提交/标识 | 最后同步时间 | 状态 |
|---|---|---|---|---|
| GitHub | **V1.17**（由规则源自动读取） | `VERSION.json.github_commit` | 自动记录 | 自动判断 |
| OpenClaw | **V1.17**（由实际加载的 `VERSION.json` 自动读取） | `sync_protocol_version` / `card_protocol_version` | 自动记录 | 自动判断 |

同步判定规则：

1. GitHub 规则源生成统一发布版本，OpenClaw 必须实际加载该版本。
2. 飞书发新卡前核对卡片协议和规则版本，并保存平台回读结果。
3. 版本号和内容标识一致时显示“已同步”；任一端落后、回读失败或 Gateway 未加载成功时显示“待同步”或“异常”，并指出具体端。
4. 发布、Gateway 重启或飞书模板变更后自动刷新；定时检查用于发现运行期间的漂移。
5. 飞书历史消息不自动改写；这里显示的是当前生效的卡片版本，不代表历史卡片已全部替换。

## 版本规则

以下任一内容发生正式变化时，必须递增版本号：

1. 报数解析、身份绑定或老板代报规则；
2. 核对卡字段、确认和重复确认逻辑；
3. OpenClaw、飞书、GitHub 的同步、回读或失败恢复规则；
4. 正式台账写入、去重、撤销或更正规则。

每次升级必须同时记录：工作台版本、GitHub commit、变更摘要和验证结果。历史版本不覆盖，只追加版本记录。
