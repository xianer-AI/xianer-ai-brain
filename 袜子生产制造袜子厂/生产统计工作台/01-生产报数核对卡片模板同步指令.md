# 生产报数核对卡片模板同步指令

> 对应工作台版本：V1.9.1

创建日期：2026-09-22
适用对象：小文CEO、生产统计工作台、飞书群生产报数核对卡片生成程序。

## 目标

小文程序里的“生产报数核对卡片”必须和《00-生产统计工作台规则.md》的最新口径一致。员工报数后，应快速返回一条简洁核对消息；收到本人回复“准确”后，才正式上传 GitHub 台账。

## 必须使用的新模板

```text
收到本次报数，系统自动识别身份如下：

身份：C = 李鸿玉，请核实

本次报数：

1. 棉堆堆袜：4800双
2. 冰冰袜：4500双
3. 小腿袜：500双
4. 过膝袜：0双（数量为0，请核实，本次未上机）
5. 女船袜：4600双
6. 男船袜：0双（数量为0，请核实）

本次已报合计：14400双

请同时核对身份和数量：

- 身份、数量都正确，请回复：**准确**
- 有错请回复：**错误**，直接重报完整、正确的六项生产数量，缺项请明确填写0
- 显示为“数量为0，请核实”的项目如果本次未生产，回复“准确”即可按 0 双上传；如果忘记上报，请直接补充数量，系统会重新生成完整核对卡

回复“准确”后，系统才正式上传台账。
```

模板中的身份、产品数量、生产日期和工序必须按实际报数替换，不能固定写成示例。

## V1.9.1 可靠性补丁

- 成功回执员工字段固定为“代号（已核实姓名）”，例如 `B（梅芳）`；仅修正显示。
- GitHub 已验证后只补发飞书成功回执，最多自动尝试3次，连续失败转人工，不重复上传。

## V1.9.1 自动上传边界

- 标准六项确认批次使用确定性计算并经过原有 guard、SHA 校验和远程回读；非标准格式进入核实流程。
- GitHub 只读请求有界超时并短重试，写入结果不明时先回读确认；上传 worker 的超时与退出只结算一次。
- 历史个人累计区兼容“个人小计/已报小计”标签；同一确认回执最多自动上传3次，固定前置校验失败停止重试；GitHub 已验证但回执发送失败只重试回执。

## 字段显示规则

- 身份必须显示为：`身份：A = 徐超超，请核实`、`身份：B = 梅芳，请核实`、`身份：C = 李鸿玉，请核实` 或 `身份：D = 张小翠，请核实`。
- 员工明确填写 `0`，或没有填写数量的产品，显示为：`0双（数量为0，请核实）`。
- 员工明确写了“本次未上机”的产品，可以显示为：`0双（数量为0，请核实，本次未上机）`。
- 员工回复“准确”后，核实项按 0 双进入上传候选；如果实际忘记上报，必须先补报并重新生成完整核对卡。

- 标准六项确认批次进入确定性上传路径；核实项经本人“准确”确认后按0双写入，同时保留原始缺报标记，不再等待模型。
- 合计按当前六项清单计算，核实项按 0 双计入。
- C=李鸿玉、D=张小翠的工序为烤边；A、B的工序为下机。C、D均按白天为主、可能加班/时间不固定处理。

## 禁止继续输出的旧卡片内容

生产报数核对卡片不得再向群里显示以下内部字段或旧话术：

- `生产报数核对 · 91f00...` 这类核对卡编号标题；
- `原报数消息：om_...`；
- `当前待核对，尚未上传。` 这类长说明可以保留含义，但不要展示内部状态编号；
- `如暂不上传，请回复“暂不上传”`；
- `不使用按钮`；
- 重复两遍“尚未上传，请回复确认”的说明；
- `员工代号：C（李鸿玉）` 这种旧格式，应改为 `身份：C = 李鸿玉，请核实`；
- 让员工回复复杂口令，例如 `C确认`、`修改数量` 加固定格式等。

## 快速回复要求

- 收到员工报数后，先快速生成核对清单并发到群里，不要等待 GitHub 写入。
- 核对清单阶段不得写正式台账。
- 收到“准确”后，再执行 GitHub 上传。
- 上传成功并完成远程回读后再回复“已上传台账”，并在详细生产数据与三项提交凭证后追加 GitHub 回执：`已更新：2026下半年下机白胚半成品统计.md`、`同步验收：全部一致`、运行时 `VERSION.json` 的实际 `生产统计工作台版本`、真实的 `远程 commit`。版本号只放在成功 GitHub 回执中，核对卡继续不展示版本号或内部 ID。
- GitHub 回执必须由本次实际上传及远程回读结果生成；上传失败、commit 缺失或回读不一致时不得显示成功回执。
- 如果 AI 服务过载或模型失败，应返回简短失败提示，并保留待核对状态，不得丢失原始报数。
