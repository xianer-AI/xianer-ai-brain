# 袜子生产统计工作台规则

## 适用范围

本规则适用于袜子生产统计工作台的群内报数、核对和 GitHub 台账入账。

当前纳入的产品：

- 冰冰袜
- 小腿袜
- 棉堆堆袜
- 女船袜
- 男船袜

“魔术袜”暂不纳入，除非另行明确启用。

## 固定流程

必须严格按以下顺序执行：

1. 收到员工报数。
2. 按**生产日**建立独立批次；每天单独记账，不把前一天数量叠加到当天。
3. 按产品和工序整理报数；产品显示固定序号：1 冰冰袜、2 小腿袜、3 棉堆堆袜、4 女船袜、5 男船袜。
4. 产品名称不同必须分别保留，不因名称相近、序号或数量相近而合并。
5. 列出本次各产品数量和当天合计，单位统一为“ 双”。
6. 对五个产品逐项核对；没有收到数量反馈的产品必须显示为“核实”，不能自动写成“未上机”。
7. 对每个显示“核实”的产品固定询问：“请确认某某产品是忘记上报数量，还是本次未上报。”
8. 等员工核对；如有补报或更正，更新清单并重新发起核对。
9. 只有五个产品整体确认“准确/确认/正确”等明确确认词后，才允许写入 GitHub 正式台账。
10. GitHub 提交成功后，必须明确报告实际上传成功；失败时必须明确报告未上传及失败原因。

## 禁止事项

- 确认前不得写入正式 GitHub 台账。
- 确认前不得说“已记录”“已上报”或“已上传”；只能说“待核对、尚未上传”。
- 未说明遗漏规格的情况下，即使回复“准确”，也不得放行上传。
- “收到”“看到了”“好的”等非明确确认，不得视为确认。
- 不得把本地测试状态、模拟消息或测试数量写入正式台账。
- 不得把员工补报、纠正或未上机说明遗漏。

## 报数口径

- A、B：下机工，记录“下机”数量。
- C：烤边或烤头工人，记录实际对应工序数量。
- 数量单位为双。
- 每名员工、每条记录单独入账，不合并覆盖原始记录。
- 同一员工不同生产日必须分开建立记录和待确认批次，不能互相覆盖或相加。
- 产品固定序号为：1 冰冰袜、2 小腿袜、3 棉堆堆袜、4 女船袜、5 男船袜；序号只是显示顺序，不是合并依据。
- 未收到产品数量反馈时，状态只能是“核实”；“未上机”不是系统默认结论。
- 原始消息 ID 用于去重，重复消息不得重复入账。

## 核对示例

收到：

```text
A 冰冰袜 下机 1000 双
A 小腿袜 下机 500 双
```

应先回复：

```text
冰冰袜：1000 双
小腿袜：500 双
合计：1500 双
暂未上报：棉堆堆袜、女船袜、男船袜。请分别说明是“忘记上报”还是“本次未上机”。
以上尚未上传 GitHub，请核对后回复“准确”；如有错误，请直接发送更正后的规格和数量。
```

只有在遗漏规格已明确处理，并收到“准确”等明确确认后，才能上传。

## 数据清理要求

验收或模拟测试产生的临时状态、测试分支和测试数量必须在测试结束后清理；正式 `main` 台账不得保留测试数据。
