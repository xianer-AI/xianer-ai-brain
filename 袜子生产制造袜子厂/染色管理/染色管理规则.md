# 染色管理规则 V3.1

生效日期：2026-09-26

## 角色
- 老板（当前同时承担家里收货确认）：确认实际实收、新价格、调价、数量/费用异常、账单和付款；以后可把实收确认权限交给指定家里收货人员，无需改动账务结构。
- 小数：后续染色模块唯一自动写入管理员。
- 染厂统计人员：确认进厂、报告染厂发回。
- 不设置送货人、发货人员为管理角色。

## 正式入账节点
- 进厂：以染厂确认收到为依据。
- 发回：染厂报告发回后记录，不等同于家里实收。
- 实收：家里点货确认后记录。

## 动态在染池
以“染厂 + 产品 + 颜色”为池键。颜色不固定，首次出现时动态建立。
同产品同颜色多次进厂后，如染厂不能指出发回属于哪次进厂：
- 不先进先出；
- 不后进先出；
- 不猜批次；
- 只保留真实日期流水，从对应产品颜色池扣减发回数量。

公式：
- 当前在染 = 累计进厂 - 累计染厂发回
- 已发未收 = 累计染厂发回 - 累计家里实收

## 防错
1. 发回不得使当前在染小于0。
2. 实收不得无依据超过已发未收。
3. 同一事件不得重复入账。
4. 产品、颜色、动作、数量或日期不明确时先待确认。
5. 发回与实收不一致时，差额进入已发未收/待核对，不直接认定丢货。
6. 历史错误采用更正记录追溯，不静默覆盖原事实。

## 日/月/年统计
### 日
当日进厂、发回、实收、日末在染、日末已发未收；支持产品、产品+颜色拆分。
### 月
月初在染、本月进厂、本月发回、本月实收、月末在染、月末已发未收。
月末在染 = 月初在染 + 本月进厂 - 本月发回。
### 年
年累计进厂、发回、实收、当前在染、当前已发未收；支持产品、产品+颜色拆分。
跨月、跨年余额不清零。

## 染色价格
价格按：染厂 + 产品 + 颜色 + 计费单位 + 单价 + 生效日期。
- 船袜、冰冰袜、小腿袜等均允许同产品不同颜色不同价。
- 不同产品同色也允许不同价。
- 物流按包管理；费用按真实计费单位（包/件/公斤/其他）计算。
- 新颜色无价格时正常记货，费用标记待定价。
- 调价新增价格版本，不覆盖历史。
- 调价前后同色货混池且计价归属不明时，不猜价，标记待确认计价。

## 染色费统计
- 日：预计染色费、确认染色费、付款、待核对费用。
- 月：确认染色费、付款、月末未付、待核对、返工、补染、加急/其他。
- 年：累计确认染色费、累计付款、当前未付、待核对、返工、补染、其他费用。
- 支持按染厂、产品、产品+颜色、月份、计费单位查询。

## 月底对账
核对产品、颜色、计费单位、计费数量、单价、金额、重复、漏账和额外收费。
一致后进入已确认应付；不一致进入待核对。
返工、补染、加急、运费等额外费用单独记录，未经确认不得自动进入应付。

## 付款
付款记录必须有日期、金额、染厂及归属账期/账单。
跨月付款只改变付款时间，不改变原染色费归属月份。
未付 = 已确认应付 - 已核销付款。
待核对金额不并入已确认应付。

## 权限
后续接入：
- 小数：只写“袜子生产制造袜子厂/染色管理/”。
- 小文：不进入染色管理群，不监听染色群原始报数；仅从 GitHub 读取小数已确认的染色汇总，不自动写染色主账。
- 飞书/OpenClaw 未接入前，不自动执行机器人写入。


## V3.1 自动化与防错增强

### 1. 发回记录号
- 每次染厂“发回”事件由小数自动生成唯一发回记录号，格式建议：FH-YYYYMMDD-序号。
- 一张发回记录可包含多个产品、多个颜色明细。
- 染厂人员和老板无需手工填写或记忆编号。
- 发回记录号用于实收匹配、防重复、异常追踪和历史查询。

### 2. 飞书消息幂等与双层防重复
- 后续飞书接入时保存飞书 message_id、业务事件ID和GitHub记录ID的关联。
- 同一 message_id 已正式入账后再次触发，不得重复写账。
- 第二层检查“染厂 + 产品 + 颜色 + 动作 + 数量 + 合理时间窗口”；高度疑似重复但 message_id 不同的事件进入“疑似重复待确认”，不得自动重复入账。
- 业务内容二次防重只能用于拦截和提示，不得自动删除真实重复发生的业务。

### 3. “确认收到”智能匹配
老板当前兼任家里实收确认人。
- 只有1笔待实收：老板回复“确认收到/收到准确/准确”等明确确认语，小数直接匹配该笔。
- 有多笔待实收，但老板回复某一条发回/待收消息：优先根据飞书 reply/reply_to 关系匹配对应发回记录。
- 有多笔待实收且老板单独发送“确认收到”：禁止猜测或全部核销，必须列出待确认记录让老板选择。
- 实收数量不符时，按老板实际确认数量记实收，差额保留为“已发未收/待核对”，不得关闭整笔。
- 实收确认本身也必须防重复，同一确认消息不得重复核销。

### 4. 已发未收超时提醒
- 只追踪“染厂已明确发回但尚未确认实收”的确定事实，不根据同色混池推断某天进厂批次是否超期。
- 每笔发回记录保留：发回时间、待实收数量、实收状态、提醒状态。
- “待实收提醒阈值”作为可配置参数，暂不写死具体小时/天数。
- 超过阈值仍未实收时进入“待实收超时”，提醒老板；确认实收后自动解除。

### 5. 每日健康检查
小数每日后台检查：
- 负在染；
- 发回超过账面在染；
- 实收超过待实收；
- 重复 message_id；
- 疑似重复业务；
- 已发未收超时；
- 待确认流水；
- 待定价；
- 缺计费单位；
- 调价/计价归属冲突；
- 待核对费用；
- 无有效价格却生成正式确认费用；
- 重复收费；
- 已核销付款超过已确认应付。

全部正常时只记录“健康检查通过”，默认不打扰老板；存在异常时只汇总需要处理的异常。

### 6. 月底结账锁定
每月状态：
- 未结账
- 待老板确认
- 已结账

老板明确确认某月账单/结账后，该月进入“已结账”。
已结账月份：
- 禁止静默覆盖历史流水、价格、费用和汇总；
- 后续发现历史错误必须建立“结账后更正”记录；
- 更正记录至少包含更正ID、原账期、对象、调整内容、原因、更正日期、确认依据；
- 原记录保留，通过更正记录重新计算受影响的当前余额、月/年汇总和费用；
- 已结账与已付款是两个独立状态：月份可以已结账但仍存在未付款。

### 结账后更正编号
建议格式：GZ-YYYYMMDD-序号。编号由系统自动生成，用户无需填写。
