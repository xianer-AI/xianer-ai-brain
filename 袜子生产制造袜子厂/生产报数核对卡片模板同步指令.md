# 生产报数核对卡片模板同步指令

创建日期：2026-09-22
适用对象：小文CEO、生产统计工作台、飞书群生产报数核对卡片生成程序。

## 目标

小文程序里的“生产报数核对卡片”必须和《生产统计工作台规则.md》的最新口径一致。员工报数后，应快速返回一条简洁核对消息；收到本人回复“准确”后，才正式上传 GitHub 台账。

## 必须使用的新模板

```text
收到本次报数，系统自动识别身份如下：

身份：C = 李鸿玉，请核实

本次报数：

1. 棉堆堆袜：4800双
2. 冰冰袜：4500双
3. 小腿袜：500双
4. 过膝袜：0双，请核实（本次未上机）
5. 女船袜：4600双
6. 男船袜：0双，请核实

本次已报合计：14400双

请同时核对身份和数量：

- 身份、数量都正确，请回复：准确
- 身份错误，请回复：身份错误，并重新发送正确身份
- 数量错误，请直接重新发送正确数量
- 未上报产品如果本次未生产，请回复“某产品未上机”；如果忘记上报，请直接补充数量

回复“准确”后，系统才正式上传台账。
```

模板中的身份、产品数量、生产日期和工序必须按实际报数替换，不能固定写成示例。

## 字段显示规则

- 身份必须显示为：`身份：A = 徐超超，请核实`、`身份：B = 梅芳，请核实` 或 `身份：C = 李鸿玉，请核实`。
- 员工明确填写 `0` 的产品，显示为：`0双，请核实`。
- 员工明确写了“本次未上机”的产品，可以显示为：`0双，请核实（本次未上机）`。
- 员工没有填写数量的产品，显示为：`未上报`。
- 合计只计算明确报出的数字；未上报项目不计入合计。
- C=李鸿玉的工序为烤边；A、B的工序为下机。

## 禁止继续输出的旧卡片内容

生产报数核对卡片不得再向群里显示以下内部字段或旧话术：

- `生产报数核对 · 91f00...` 这类核对卡编号标题；
- `原报数消息：om_...`；
- `当前待核对，尚未上传。` 这类长说明可以保留含义，但不要展示内部状态编号；
- `如暂不上传，请回复“暂不上传”`；
- `不使用按钮`；
- 重复两遍“尚未上传，请回复确认”的说明；
- `员工代号：C（李鸿玉）` 这种旧格式，应改为 `身份：C = 李鸿玉，请核实`；
- 让员工回复复杂口令，例如 `C确认`、`修改数量` 加固定格式等。

## 快速回复要求

- 收到员工报数后，先快速生成核对清单并发到群里，不要等待 GitHub 写入。
- 核对清单阶段不得写正式台账。
- 收到“准确”后，再执行 GitHub 上传。
- 上传成功后再回复“已上传台账”。
- 如果 AI 服务过载或模型失败，应返回简短失败提示，并保留待核对状态，不得丢失原始报数。
