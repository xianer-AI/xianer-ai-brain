# 个人 AI 知识库

这是一个面向个人和 Agent 使用的 LLM Wiki。知识库强调两件事：

1. **事实与知识分离**：事实是可追溯的原始信息，知识是基于事实整理出的可复用结论。
2. **人机协作维护**：人负责判断重要性、可信度和最终取舍，Agent 负责整理、链接、检索和发现冲突。

## 使用规则

### 新内容如何进入知识库

1. 先放入 `04-inbox/`，保留原始上下文和来源。
2. 能确认来源和原文的内容，整理到 `01-facts/`。
3. 经过比较、归纳、解释或验证后，才整理到 `02-knowledge/`。
4. 在事实页和知识页之间使用相对链接，形成可追溯链路。
5. 在 `03-index/index.md` 增加入口；无法归类的内容先留在收件箱。

### 文件命名

- 使用小写英文、数字和短横线：`topic-name.md`
- 文件名表达主题，不使用 `新建文档`、`最终版` 等临时名称。
- 日期记录使用 `YYYY-MM-DD`，例如 `2026-09-12`。
- 一篇文档尽量只表达一个清晰主题。

### 事实和知识的边界

| 类型 | 放置位置 | 判断标准 |
| --- | --- | --- |
| 事实 | `01-facts/` | 可以指向来源、原文或明确的观察记录 |
| 知识 | `02-knowledge/` | 对事实进行了抽象、解释、比较、推导或形成了行动方法 |
| 未整理内容 | `04-inbox/` | 还没有完成来源确认、分类或提炼 |
| 过时内容 | `99-archive/` | 不再作为当前结论使用，但仍有保留价值 |

## 给 Agent 的最短指令

处理一条新信息时，请遵循：

```text
读取 00-system/agent-protocol.md
保留来源和上下文
先写入 04-inbox/
事实写入 01-facts/
知识写入 02-knowledge/
建立双向或单向相对链接
更新 03-index/index.md
标记不确定性、冲突和待验证项
```

## 状态标记

- `inbox`：尚未整理
- `draft`：已整理但待验证
- `verified`：来源已核实或事实已确认
- `evergreen`：适合长期复用的知识
- `outdated`：内容可能已经过时
- `archived`：已归档，不作为当前结论

详细规则见 [`00-system/agent-protocol.md`](00-system/agent-protocol.md)。
