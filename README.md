# 个人 AI 知识库

这是一个面向个人和 Agent 使用的 LLM Wiki。知识库强调两件事：

1. **事实与知识分离**：事实是可追溯的原始信息，知识是基于事实整理出的可复用结论。
2. **人机协作维护**：人负责判断重要性、可信度和最终取舍，Agent 负责整理、链接、检索和发现冲突。

## 目录结构

```text
.
├── 00-system/                 # 知识库规则、元数据、Agent 工作协议
├── 01-facts/                  # 事实层：原始记录、来源、观察和引用
├── 02-knowledge/              # 知识层：整理、解释、方法和决策
├── 03-index/                  # LLM Wiki 导航和检索入口
├── 04-inbox/                  # 临时收件箱：尚未整理的内容
├── 99-archive/                # 归档：过时、合并或删除前保留的内容
├── 袜子生产制造袜子厂/          # 袜子项目的自包含资料目录
└── README.md
```

## 使用规则

### 新内容如何进入知识库

1. 先放入 `04-inbox/`，保留原始上下文和来源。
2. 明确属于某个项目的内容，整理后放入对应项目目录。
3. 跨项目的事实整理到 `01-facts/`，跨项目的知识整理到 `02-knowledge/`。
4. 在事实页、知识页和项目资料之间使用相对链接，形成可追溯链路。
5. 在 `03-index/index.md` 增加长期入口；无法归类的内容先留在收件箱。

### 文件命名

- 文件名表达清晰主题，不使用“新建文档”“最终版”等临时名称。
- 日期记录使用 `YYYY-MM-DD`，例如 `2026-09-12`。
- 一篇文档尽量只表达一个清晰主题。
- 同一产品的持续变化优先在固定主文件中迭代，并在文件内部保留更新记录。

### 事实和知识的边界

| 类型 | 放置位置 | 判断标准 |
| --- | --- | --- |
| 项目资料 | 对应项目目录 | 明确服务于某个项目，可在项目目录内继续分类 |
| 事实 | `01-facts/` | 可以指向来源、原文或明确的观察记录 |
| 知识 | `02-knowledge/` | 对事实进行了抽象、解释、比较、推导或形成了行动方法 |
| 未整理内容 | `04-inbox/` | 还没有完成来源确认、分类或提炼 |
| 过时内容 | `99-archive/` | 不再作为当前结论使用，但仍有保留价值 |

## 给 Agent 的最短指令

```text
读取 00-system/agent-protocol.md
保留来源和上下文
明确属于项目的内容放入对应项目目录
跨项目事实写入 01-facts/
跨项目知识写入 02-knowledge/
建立相对链接
更新 03-index/index.md
标记不确定性、冲突和待验证项
知识库有变动后提交并推送到 origin/main
```

## 状态标记

- `inbox`：尚未整理
- `draft`：已整理但待验证
- `verified`：来源已核实或事实已确认
- `evergreen`：适合长期复用的知识
- `outdated`：内容可能已经过时
- `archived`：已归档，不作为当前结论

详细规则见 [`00-system/agent-protocol.md`](00-system/agent-protocol.md)。
